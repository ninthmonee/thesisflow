**TradingAgents 美股投研工作台功能设计与技术选型方案**

版本：方案 v1.2。更新日期：2026-10-27。本文主体保留最初功能设计依据；当前应用已实现多项能力及账号隔离，实际范围见 [实现状态](web-execution-status.md)。TypeScript 7 + Orval + Oxc 技术基线保持，实施任务见 [实现方案](./web-implementation-plan.md)。

本地 Agent 执行与模型接入按新增的 [本地 Agent Runtime 与模型接入设计](local-agent-runtime-design.md) 演进：区分模型服务、执行机器/Runtime、研究 Agent 和研究执行方案；保留内置12角色，增加独立Agent研究及后续混合研究。该增量方案已完成参照分析，Runtime桥接尚未实施；与本文早期规划冲突时，以增量方案和实际交付状态为准。

适用范围：先在本机供个人使用，完成后支持少量朋友独立使用，为后续产品化保留演进路径。现有 8000 应用和 8011 交互草稿均不代表本文全部功能已经完成。

**一、产品定位与设计原则**

产品定位是以 TradingAgents 个股研究为核心的美股投研工作台。用户能完成“配置模型与数据 → 建立自选 → 观察市场和个股 → 发起多角色研究 → 查看过程与证据 → 留存和比较报告”的完整流程。

核心研究保持独立一级入口。行情、市场情绪、行业轮动与资金数据为研究提供上下文。模型连接属于设置能力，不占据主要行情空间。

- 首期重点为美股普通股与 ETF 行情；个股公司研究优先覆盖美股普通股。ETF 与指数按照证券类型使用适配的分析工具，不套用公司财报流程。
- 复用 TradingAgentsGraph 与已有分析角色，不另写一个只有问答或报告摘要的研究引擎。
- 数值来自数据与计算服务；模型解释已取得的事实。缺数据、未接入、延迟、估算、模拟都应直接标注。
- 默认配置足够开始使用，角色覆盖、模型参数和数据路由放入高级设置。
- 行情刷新、指标计算和模型调用独立控制；刷新图表不产生研究调用。
- 本方案不包含实盘下单、完整券商账户系统、全市场 Level 2 盘口、任意工作流拖拽编排。图表不是行情数据服务。

**二、现有能力与改造边界**

| 领域 | 现有项目事实 | 新版改造 |
|---|---|---|
| 个股研究 | 四分析师、多空辩论、研究经理、交易员、三类风险观点、组合经理 | 原样保留研究链路，增加模板、结构化结果与证据关联 |
| Web 执行 | 创建研究、阶段动态、SSE、报告与历史 | 迁移为 React 页面，补任务恢复、取消与分页 |
| 模型适配 | 多厂商客户端、quick/deep 两档模型 | 新增连接管理与凭据解析，按角色解析模型 |
| 模型设置 | 只读展示，主要依赖环境配置 | 新增可编辑、可持久化的连接、模型配置和检测 API |
| 行情 | 研究工具主要使用日线数据与文本指标 | 新增数值行情 API、分钟适配器、日历和图表服务 |
| 自选 | 固定示例按钮，无自选持久化 | 证券搜索、加入/移除、分组、排序、持久化 |
| 市场与资金 | 缺少完整市场可视化聚合模块 | 新增情绪、广度、相对强弱、成交关注及有来源的资金数据 |
| 任务持久化 | 内存任务、daemon 线程、JSON 快照；重启标记 interrupted | 数据库任务、独立 worker、事件日志、心跳租约 |
| 朋友使用 | 默认仅允许本机 | 在网络开放前增加登录、权限、工作区隔离 |

原有日线清洗会把时间归一到本地午夜；缓存主要按代码组织。它不能直接用于分钟图。现有图检查点也不等于 Web 已具备可靠自动恢复。

**三、信息架构与页面入口**

| 一级入口 | 页面及主要内容 | 主要操作 |
|---|---|---|
| 个股研究 | 新建研究、运行详情、最新结果 | 启动 TradingAgents 分析、查看阶段报告 |
| 行情工作台 | 自选、证券搜索、报价、图表、事件、最近研究 | 切换股票、周期、指标、加入自选、发起研究 |
| 市场脉搏 | 大盘、波动、广度、期权结构、新闻叙事、事件 | 切换观察窗口、查看证据、生成市场简报 |
| 板块与资金 | 行业/主题热力图、相对强弱、成交关注、ETF 资金 | 排序、下钻股票、加入自选、发起研究 |
| 研究记录 | 历史任务、报告、标签、比较、导出 | 搜索、筛选、打开、重新研究 |
| 设置中心 | 模型连接、角色模型、数据源、模板、偏好 | 新增连接、检测、保存、版本管理 |

全局工具栏提供证券搜索、任务中心与连接状态。自选作为行情工作台的常驻侧栏；任务中心可从任意页面进入。首次访问进入初始化向导，完成后默认进入个股研究，用户可修改默认首页。

建议路由：/research/new、/runs/:runId、/stocks/:instrumentId、/market、/sectors、/reports、/settings/models、/settings/data、/settings/templates。持久化使用标准证券 ID，URL 展示名称不作为唯一主键。

**四、首次使用流程**

1. 显示当前模型、行情、新闻、宏观等能力的真实状态，区分“未配置”“未检测”“可用”“受限”“不可用”。
2. 创建模型连接：选择供应商与认证方式，输入凭据，选择或手填模型 ID，保存并检测。
3. 选择默认研究模型与默认模板；需要时才展开角色覆盖。
4. 配置数据源。允许先用已有日线来源；分钟、资金、期权等未接入能力显示明确状态。
5. 搜索并加入第一只股票，发起一次真实研究。

允许保存尚未检测的配置，但运行前必须完成必要的能力检查。缺少可选数据时允许按模板策略继续，报告注明影响；缺少必需价格或必需模型能力时阻止启动并给出可操作原因。演示模式使用独立数据标记，不能显示真实连接成功。

**五、TradingAgents 个股研究功能**

默认表单包含：股票、分析日期、研究模板、报告语言。展开高级设置后可选择四类分析师、辩论/风险讨论轮数、工具轮数、角色模型覆盖、来源策略和运行限制。

模板建议包括：快速研究、标准研究、深度研究、自定义模板。模板只是设置组合，不能以“深度”命名暗示结论必然更准确。模板保存版本，修改后不改变已经生成的报告。

研究链路：技术/基本面/新闻/情绪分析师并行 → 多头与空头研究 → 研究经理汇总 → 交易员提案 → 激进/中立/保守风险讨论 → 组合经理最终决策。

| 环节 | 界面保留的输出 |
|---|---|
| 四类分析师 | 各自报告、数据来源、缺失项、已完成状态 |
| 多空研究 | 双方依据、争议点、轮次、研究经理判断 |
| 交易提案 | 有数据支持的研究提案与条件；无有效字段时不补数 |
| 风险讨论 | 三类风险观点、主要假设、风险汇总 |
| 最终决策 | 评级/判断、主要依据、分歧、风险、数据截止时间 |

研究页面显示阶段与角色状态、公开的阶段报告、工具调用摘要、耗时和可获得的用量。进度未知时展示阶段，不编造完成百分比。用户切页或关闭浏览器不影响服务端任务。

研究时间语义：当前接口只接收 YYYY-MM-DD。第一步保留并明确日级口径；盘中研究需新增带时区的 as_of 时间戳，所有工具按信息公开时间统一截断后才开放。把日期切到过去不足以实现可靠历史研究。修订财报、历史成分股、宏观数据修订、复权口径均需披露其时间边界；无法满足当时可得性时标记为回顾分析。

**六、任务、取消、恢复与报告**

任务状态采用 queued、running、cancelling、cancelled、completed、failed、interrupted。研究阶段单独记录；数据质量另设 complete、partial、unavailable，不把三类状态混成一个字段。

- 取消排队任务立即生效；运行中取消在模型/工具或节点可中止边界生效，已发生调用无法撤销费用。
- 继续研究仅恢复兼容检查点，保留原运行配置与快照，新增 attempt；配置或执行图不兼容时创建新运行。
- 重新研究生成新的 run，并允许使用最新数据和配置；与继续原研究是两个操作。
- 外部调用中崩溃可能无法确定调用是否已完成。恢复标记此类不确定步骤，不承诺外部调用恰好执行一次。
- SSE 使用持久化序号补齐断线事件；事件已归档时返回最新状态并说明需要重同步。

报告分为结论概览、依据与分歧、四类分析、多空研究、交易提案、风险讨论、最终决策、运行信息。支持 HTML、Markdown 导出。新结果采用可校验的结构化对象与 Markdown 双存；图表上的价格线仅使用有单位、时间和证据引用的有效结构化字段。

报告绑定不可变 RunManifest：标的、研究时间、模板版本、实际角色模型、参数、来源链、数据快照引用、提示词/图版本、记忆范围及实际降级记录。凭据仅保存引用，不进入报告。固定的报告不能被最新行情或设置变化覆盖。

历史支持代码、日期、状态、模板和模型筛选，分页读取。比较两个运行时说明数据、配置和模型差异；只有共同冻结的数据快照和工具响应，才可称为控制输入后的模型比较。即使输入固定，生成结果也不保证逐字一致。

**七、自选股管理**

入口包括侧栏“＋”、全局证券搜索结果、股票详情星标、板块下钻列表。搜索展示代码、名称、交易所、证券类型与币种，处理不同来源的代码别名。

基础功能为加入、移除、撤销移除、拖动/按钮排序、分组、新建/重命名/删除分组、批量移动和删除。默认分组“我的自选”开箱可用；删除含股票分组时明确股票的移动或移除方式。

同组按标准证券 ID 去重；同一股票可属于不同分组。移除关注不删除报告。刷新和重启保留列表、顺序和偏好。未取到行情时保留自选项并显示原因。未来朋友模式下，列表默认按用户私有；共享工作区列表是显式动作。

**八、专业美股行情工作台**

布局采用左侧自选、中间报价与主图、右侧事件与最近研究、下方指标与研究结果。股票顶部固定“启动 TradingAgents 分析”和“查看最近研究”。支持面板尺寸与布局恢复，桌面优先，小屏切换为标签页。

| 内容 | 功能及口径 |
|---|---|
| 报价头部 | 最新价、常规时段涨跌、盘前/盘后单独变化、成交量/额；缺失项留空 |
| 主图 | 分时与 K 线，日/周/月及来源支持的分钟周期，缩放、平移、十字线、历史加载 |
| 副图 | 成交量、SMA/EMA、RSI、MACD、BOLL、ATR；参数可保存 |
| 基准 | 默认 SPY，可选择其他合适基准；归一化比较与原始价格分别显示 |
| 时段 | 常规、盘前盘后切换，交易日历处理节假日、提前收市和夏令时 |
| 研究联动 | 最近研究时间、结论、报告入口；有效结构化价位和事件可定位图表 |

报价、分钟线和日线可以由不同能力服务提供，但必须展示来源与口径。统一保存 UTC 时间戳与交易所时区，默认显示 America/New_York，可切换本地时区。未完结 K 线标明进行中；停牌、休市、缺失不能补成虚假成交。

价格调整显式区分 raw、split-adjusted、total-return；研究与图表使用不同口径时给出提示。日线派生周/月线需遵循交易日历。VWAP 若由分钟柱近似计算，应标明近似和重置时段。基础买卖报价是否为单市场、合并报价或 NBBO 由数据能力决定；不把单一市场报价标成全市场。

UI 默认深色、绿涨红跌，可切换主题与配色；使用等宽数字、USD 与 K/M/B 明确单位、紧凑表格、少量状态色。颜色同时配合正负号和文本。加载、空列表、无权限、受限、断线、过期、部分失败都有独立状态。

**九、市场脉搏与情绪分析**

观察窗口提供当前交易日、最近 5 个交易日、最近 1 个月，页面同时显示实际起止时间。比较使用共同数据截止时间；未完成交易日和已完成交易日口径明确区分。

| 维度 | 指标 | 解释边界 |
|---|---|---|
| 大盘 | 标普、Nasdaq-100、小盘、道指；无指数授权时用 SPY/QQQ/IWM/DIA 代理并标注 | ETF 代理与真实指数不混称 |
| 波动预期 | VIX、变化、注明历史区间的分位；有数据再加期限结构 | 反映预期波动，不等同上涨/下跌概率 |
| 市场广度 | 涨跌家数、均线上方比例、新高新低 | 必须注明股票池版本、有效覆盖和时间 |
| 期权结构 | Equity/Index/Total Put/Call 分开，注明成交量或持仓口径 | 单项比率不直接推出机构净买入 |
| 风险偏好 | 成长/价值、小盘/大盘、防御/周期相对表现 | 使用可解释的比较组合 |
| 新闻与社交 | 主题、来源、样本数、去重、立场与模型解读 | 属于样本叙事，不能代表全市场投资者 |
| 事件背景 | 财报、宏观数据发布、政策事件 | 展示已确认时间、实际/预期/前值的来源与版本 |

默认提供证据面板，不合成不透明的“恐惧贪婪分数”。后续自定义综合指标需公开权重、标准化方法、缺失处理与版本。

市场简报由已计算的数据快照生成，输出“状态、相对前期变化、关注方向、分歧、风险、证据与截止时间”。缺少关键维度时注明覆盖不足；允许出现指数上涨但广度收窄等分歧。

VIX 的含义依据 [Cboe 说明](https://www.cboe.com/tradable-products/vix/term-structure/)；Put/Call 的区分依据 [Cboe 统计](https://www.cboe.com/markets/us/options/market-statistics/daily)。这些公开说明是口径依据，不代表已取得自动化数据接口或再分发授权。

**十、行业轮动与资金关注**

行业与主题分开维护：行业采用有版本的分类；首期可使用 11 个行业 ETF 作为行业表现代理。主题如半导体、AI 基建等是独立成分组合，注明成分、权重、创建者和生效时间。

页面提供热力图、排名、时间序列与成分下钻。价格指标、成交关注、资金变化为可切换的独立视图。

| 层次 | 指标 | 可以表达什么 |
|---|---|---|
| 相对强弱 | 同窗口收益、相对 SPY 收益差（百分点） | 哪些方向跑赢或落后 |
| 交易关注 | 成交额、RVOL、活跃股票比例 | 哪些方向更活跃 |
| ETF 资金 | 有来源的净申赎与累计值，实际/估算分开 | ETF 份额净变化对应的资金规模 |
| 机构披露 | 13F 季度持仓变化及公开时间 | 滞后的持仓观察 |

默认日内 RVOL 为当前常规时段累计量 / 过去 20 个有效同类交易日同一 ET 时刻平均累计量。页面注明基准样本；有效样本不足时不计算。提前收市日使用匹配口径，不能直接与完整交易日比较。日级 RVOL 单独定义为日量与历史日均量之比。

成交额不是净流入。ETF 市场成交不是净申赎；份额变化也不能直接当成成分股净买入。AUM 变化需剔除价格与分红等影响后才可能用于估算，且始终标为估算。行业聚合资金要注明覆盖的 ETF 池，避免把样本合计称为整个行业资金。

13F 不作为实时资金指标，季度市值变化不直接等于买入金额。口径依据 [ICI ETF 机制](https://www.ici.org/faqs/faqs_etfs) 与 [SEC 13F 说明](https://www.sec.gov/rules-regulations/staff-guidance/frequently-asked-questions-about-form-13f)。首版未取得可靠净申赎数据时保留能力状态与接入入口，不以模拟数据填充真实页面。

**十一、多厂商模型中心**

模型供应商、连接、模型配置、角色绑定是四个对象。首期连接 OpenAI、DeepSeek、Anthropic、Google、通用兼容接口与本地服务；可复用现有 Azure/Bedrock 适配能力，界面按需逐步开放。

| 对象 | 主要字段和操作 |
|---|---|
| ProviderDefinition | 厂商 ID、协议、默认地址、认证字段、可支持能力 |
| ModelConnection | 名称、厂商、认证类型、credential_ref、地址、所有者、启用状态 |
| ModelProfile | 连接、精确模型 ID、参数、能力、检测结果与时间 |
| RoleBinding | 模板版本、角色、模型配置、备用策略 |

新增连接必须有供应商选择、认证方式、密钥/授权入口、接口地址和连接名称。API Key 使用密码输入，保存后只显示掩码；编辑空密钥表示保持原值，替换/删除密钥采用明确操作。

模型选择优先使用厂商可用的模型发现接口，同时支持手填 ID；不假定所有厂商都有统一 /models 接口。模型能力包括工具调用、结构化输出、流式返回及实际支持的参数。检测区分配置保存、身份/连接检查、模型可调用检查和能力检查；可能产生调用的检查需在按钮旁说明。

默认模型覆盖全团队；高级设置允许每个角色覆盖，保留现有 quick/deep 配置作为兼容默认。RoleModelResolver 按不可变运行配置解析角色模型；不通过临时修改进程环境变量切换账号。

保存“未检测”配置与启用研究分开。更改模型 ID、地址或凭据后使原检测状态失效。不支持的能力阻止使用或采用显式、已验证的降级路径。客户端为每个运行提供明确凭据，不因缺少环境变量而提前拒绝一个有显式密钥的连接。

支持同厂商多连接、编辑、停用、测试、配置复制（不复制密钥）、默认模型、角色绑定、有限重试与备用模型。每次实际模型切换写入报告；失败不静默替换。费用以厂商实际返回为准，无价格依据时仅显示用量或未知，估算与实际分开。

当前已有登录授权可作为独立认证适配保留，并按其实际可用范围检测；本机登录状态不能自动视为朋友或服务端用户可共享的凭据。

**十三、配置、模板与扩展性**

配置解析顺序为系统默认 → 工作区默认 → 模板版本 → 本次覆盖；管理员硬限制不可被普通覆盖绕过。解析结果形成 RunManifest，可查看每项配置来自哪一层。

界面按三层展开：基础（股票/日期/模板）、进阶（角色/深度/模型）、高级（厂商参数/数据链/运行限制）。模板可复制、保存新版本和停用；被历史引用的版本不可原地修改。

采用代码级注册与声明式配置：ProviderAdapter、MarketDataAdapter、IndicatorDefinition、ReportSectionDefinition、ResearchTemplate。新增厂商通常增加适配器与能力声明；新增指标同时定义输入、计算、单位、预热期、展示和测试。首期不从 UI 上传任意 Python/JavaScript，也不承诺任意角色拓扑自动拼装。

**十四、权限与部署模式**

本机模式默认仅监听回环地址，创建默认本机用户与工作区，避免后续数据结构迁移。即使本机也校验 Origin/Host，敏感写操作使用会话与防跨站请求保护。

朋友模式必须先加入登录、会话和工作区授权，再开放网络。工作区角色为 Owner、Researcher、Viewer；成员默认私有自选与报告，可显式分享到工作区。

| 能力 | Owner | Researcher | Viewer |
|---|---|---|---|
| 浏览获授权行情/共享报告 | 是 | 是 | 是 |
| 发起研究 | 是 | 按额度 | 否 |
| 管理个人连接/自选 | 是 | 是 | 自选按产品策略 |
| 管理共享连接与成员/额度 | 是 | 否 | 否 |
| 查看已保存密钥明文 | 不通过业务 API 返回 | 不返回 | 不返回 |

私有连接仅所有者可使用；共享连接要有明确授权和配额，使用者不获得原始密钥。API、SSE、下载、图表快照和文件引用都执行同样的对象级权限检查。

本机密钥优先存系统钥匙串；服务部署使用加密秘密存储，主密钥独立于数据库和代码。备份、日志和导出不包含凭据明文。自定义端点仅管理员/连接所有者在授权范围配置，部署模式限制内网访问与外发目标，保护其他用户凭据。

共享先支持带权限的报告快照；公开链接、定时研究、告警、完整组合模拟、跨模型评估与计费属于后续扩展。

**十五、前端技术选型与 SPA/Next.js 决策**

选型：React + TypeScript + Vite SPA。研究引擎和 API 继续由 Python 提供。开发时 Vite 代理 /api；正式构建后由 FastAPI 或反向代理同源提供静态资源。本机正式使用不需要额外启动 Node 应用服务器。

本产品以登录后的交互工作台、图表与长任务为主，当前不依赖公开页面 SEO 或服务端渲染；因此不增加 Next.js 服务端层。Next.js 同样可以构建 SPA，本选择来自当前产品边界，而非其不支持图表或交互。未来公开内容/研究展示站确实需要 SSR/SEO 时，可独立采用 Next.js 并复用 API。[Next.js SPA 文档](https://nextjs.org/docs/app/guides/single-page-applications)、[Vite 文档](https://vite.dev/guide/)

版本核验日期为 2026-10-24。下列是建议的精确开发基线；已完成独立最小契约生成与 TypeScript 7 检查，不代表新版完整应用已经安装或通过集成构建。实施第一步应生成并提交锁文件，运行安装、质量检查和构建；不使用 --force/忽略 peer 冲突来宣称兼容。

**十五附、Oxc 质量工具链设计**

使用 Oxlint、oxlint-tsgolint 和 Oxfmt；Python 保持 Ruff。首期不同时配置 ESLint、typescript-eslint 或独立 Prettier 对相同文件重复检查。Oxfmt 部分格式使用包内的 Prettier 实现，不等于项目需要另维护一套格式工具。

| 门禁 | 工具 | 检查范围 |
|---|---|---|
| 普通 lint | Oxlint | 代码错误、React/Hooks、导入、可访问性与测试规则 |
| 类型感知 lint | Oxlint --type-aware + tsgolint | Promise 误用、遗漏等待等依赖类型信息的规则 |
| 格式检查 | Oxfmt --check | 手写前端源文件、脚本和配置 |
| 正式类型检查 | TypeScript 7 tsc --noEmit | 应用、生成契约代码、脚本和构建配置 |
| Python 质量 | Ruff 0.17.2 + pytest 9.1.1（现有） | 修改的后端模块及必要核心回归 |

Oxlint 的 --type-check 在当前 CLI 文档仍为实验性，本方案不依赖它替代正式 tsc。采用稳定 JSON 配置 .oxlintrc.json 与 .oxfmtrc.json，避免首期引入动态配置、React Compiler 规则或 JS 插件 API 等额外实验特性。

显式启用所需的 typescript、react、jsx-a11y、import、vitest、unicorn、oxc 原生插件。plugins 字段会覆盖默认集合，不能仅加入 react 而意外关闭其他所需集合。规则按锁定版本验证，首期重点为 react/rules-of-hooks、react/exhaustive-deps、typescript/no-floating-promises、typescript/no-misused-promises；React Refresh 的 react/only-export-components 按组件文件启用，Vite 允许常量导出。不要把某个原生插件的存在等同于覆盖整个 ESLint 生态。

lint 与格式默认只检查新 frontend 范围；dist、coverage、依赖、行情缓存、旧应用静态文件和历史报告不做全量格式迁移。自动修复只由开发者在本地显式执行，CI 不写入修复，也不默认启用危险修复。

生成文件单独放在 frontend/src/shared/api/generated，禁止手改。选择从手写代码 lint/format 中排除，由固定 Orval 版本直接生成并进行漂移比较；它们仍必须进入 TypeScript 7 检查和构建。若未来决定格式化生成物，应把固定 Oxfmt 步骤加入唯一生成流水线，不能靠开发者各自格式化。

本地与 CI 的逻辑顺序为：导出/校验 OpenAPI → Orval 生成与漂移检查 → Oxfmt 检查 → Oxlint 类型感知检查 → 正式 tsc → Vitest → Vite 构建 → 关键流程 Playwright。依赖安装和生成完成后，互不依赖的只读检查可以并行；普通 lint 可作为快速本地入口，完整 lint 运行时无需在 CI 重复执行相同规则。

正式类型门禁显式指定 tsconfig.app.json 和 tsconfig.node.json，前者包含 src 与 generated，后者包含构建/测试/生成配置和脚本。不能对只有空 files 与 references 的根配置执行一次裸 tsc --noEmit 就视为全量检查；M0 使用代表性反例确认应用、生成文件和工程配置确实在检查范围内。

2026-10-24 的临时最小验证已通过：锁定 Oxc 组合检查 React 19 Hooks 与 Promise 代码；一个故意遗漏处理的 Promise 被 no-floating-promises 阻止；移除反例后类型感知 lint 与 Oxfmt 格式检查通过；包含 Orval 生成代码和 React TSX 的 TS 7.0.2 strict 检查通过。验证不修改项目依赖，也不代表新版 Vite 应用或全部规则集已经集成通过。

口径依据：[Oxlint 类型感知](https://oxc.rs/docs/guide/usage/linter/type-aware.html)、[CLI 的实验性 type-check](https://oxc.rs/docs/guide/usage/linter/cli.html)、[插件](https://oxc.rs/docs/guide/usage/linter/plugins.html)、[Oxfmt 配置](https://oxc.rs/docs/guide/usage/formatter/config.html)。具体脚本、目录和阶段任务见 [实现方案](./web-implementation-plan.md)。

**十六、后端与运行架构**

架构采用模块化单体，加独立研究 worker。API 处理认证、配置、查询和任务命令；研究 worker 执行现有图；行情采集与市场聚合采用独立调度和有界 I/O 执行通道，不与串行研究任务共用阻塞队列。长时间研究不能阻塞行情刷新，无需因此拆成微服务。浏览器只访问本系统 API。

| 层次 | 技术基线 | 设计说明 |
|---|---|---|
| Python | 3.13.3（现有） | 保留现有可运行环境 |
| API | FastAPI 0.162.0、Pydantic 2.14.1、Uvicorn 0.54.0（现有） | 路由、验证、OpenAPI |
| 投研编排 | LangGraph 1.2.17、langchain-core 1.7.0（现有） | 复用核心，按角色注入客户端 |
| 业务存储 | SQLite WAL + SQLAlchemy 2.1.6 | 配置、自选、运行、事件与权限 |
| 数据迁移 | Alembic 1.20.1 | 有版本的 schema 升级 |
| 数值数据 | 现有 pandas/stockstats，新增 PyArrow 26.0.0 | 指标与 Parquet 行情/快照 |
| 日历 | exchange-calendars 4.13.2 + zoneinfo | 美股时段与时区；定期更新日历 |
| 研究事件 | SSE + 持久化序号 + 查询兜底 | 单向任务动态、重连补齐 |
| 行情更新 | 初期可见标的轮询；有订阅能力后 WebSocket 网关 | 上游连接在后端复用，不暴露凭据 |

现有版本来自本机安装核验。新增 Python 组件来自 [PyPI SQLAlchemy](https://pypi.org/pypi/SQLAlchemy/2.1.6/json)、[Alembic](https://pypi.org/pypi/alembic/1.20.1/json)、[exchange-calendars](https://pypi.org/pypi/exchange-calendars/4.13.2/json)、[PyArrow](https://pypi.org/pypi/pyarrow/26.0.0/json) 的发布元数据，尚未安装验证。

初期一个 API 进程、一个研究 worker，研究任务默认串行；每次研究内部仍保留分析师并行。用户可降低模型连接并发，管理员限制总并发。SQLite 采用短事务与批量事件，不在模型调用期间持有写锁。数据库在本机磁盘，不放在网络共享盘。

任务先持久化再返回 202，worker 原子领取，使用心跳、租约与提交令牌防止过期 worker 覆盖结果。队列采用至少一次执行语义，内部写入幂等，外部模型调用不承诺恰好一次。事件追加写入；正文文件原子落盘后更新索引。API 的进程内后台线程不承担可靠长任务。

多进程/多机写入和排队成为瓶颈时迁移 PostgreSQL 与专门队列；行情/报告文件迁移对象存储。业务服务依赖仓储接口，不直接依赖 SQLite 文件路径。首期不引入 Kubernetes、向量数据库或无明确用途的 Redis。

**十七、模块与数据模型**

后端边界为 API → application services → domain services → adapters。建议新增 research、models、market_data、market_intelligence、workspace、infrastructure 模块，保留 graph/agents/llm_clients/dataflows 作为可复用核心与适配层。

前端按 app、features/research、features/market、features/stocks、features/watchlists、features/models、features/settings、shared/api、shared/ui、shared/charts 划分；不在页面直接拼接供应商请求。

| 对象组 | 主要对象 |

| 证券与自选 | Instrument、SymbolAlias、Watchlist、WatchlistItem、ThemeVersion |
| 模型与数据配置 | ModelConnection、ModelProfile、RoleBinding、DataConnection |
| 模板与执行 | ResearchTemplateVersion、Run、RunAttempt、RunEvent、RunManifest |

| 行情与聚合 | BarPartition、QuoteSnapshot、IndicatorSeries、MarketSnapshot、FlowObservation |

所有业务对象预留 workspace_id、owner_id、created_at、updated_at；必要唯一键包含工作区。时间存 UTC，金额带币种，价格精度由证券定义，缺失与零严格区分。大规模分钟柱不逐条塞进任务 JSON。

行情文件按来源/feed、instrument、interval、session、adjustment 与日期分区；缓存键包含这些维度与版本。研究快照和引用记录哈希、来源、公开/采集时间及有效期。缓存清理不删除仍被保留报告引用的快照。

现有记忆按 ticker/date 共享，需新增 workspace 与记忆策略范围；跨模型实验默认隔离记忆，或固定共同记忆快照。不同用户的研究经验不可隐式混用。

**十八、API 契约**

| 资源 | 拟定接口 |
|---|---|
| 初始化与能力 | GET /api/v1/bootstrap、/capabilities |
| 证券 | GET /api/v1/instruments/search、/instruments/{id} |
| 自选 | /api/v1/watchlists 及 /{id}/items 的创建、查询、修改、移除、排序 |
| 模型连接 | /api/v1/model-connections CRUD；/{id}/test；模型发现；model-profiles |
| 数据连接 | /api/v1/data-connections CRUD、检测、能力、缓存状态 |
| 模板 | /api/v1/research-templates、版本、角色绑定 |
| 研究 | POST /api/v1/runs；GET /runs、/runs/{id}；POST cancel/resume/clone |
| 事件与报告 | GET /runs/{id}/events、/reports、/exports |
| 行情 | GET /api/v1/market/quotes、/bars、/indicators、/calendar |
| 市场分析 | GET /api/v1/market/pulse、/breadth、/sectors、/attention、/etf-flows |
| 朋友模式 | /api/v1/session、/workspaces、/members、/shares |

创建研究支持客户端幂等键；配置修改使用版本检查，避免覆盖别人刚保存的变更。统一错误包含 error_code、用户可读信息、是否可重试和 trace_id，不返回上游认证头或完整秘密地址。密钥字段只写不读。

FastAPI/Pydantic 作为契约源，导出固定 OpenAPI 后由 Orval 生成前端类型和请求/Query 集成；Zod 校验动态模板、事件和第三方边界。生成请求必须通过明确配置的 mutator/适配接入统一 transport，非 2xx 抛出可识别的 ApiError；TanStack Query 的 TError 类型声明不能代替真实抛错。SSE 事件有 event_id、run_id、attempt_id、type、timestamp、schema_version、payload；EventEnvelope 作为显式判别联合加入导出 schema。SSE 帧读取、event ID 与断线续传使用独立 transport，不能把 text/event-stream 当作普通 JSON SDK 请求。原生 EventSource 采用同源 Cookie 会话；需要自定义请求头时改用支持流读取的 fetch transport。兼容旧 /api/runs 期间保留迁移适配和同样的授权，待新版核心回归通过后再退役旧入口。

**十九、质量、性能与运维目标**

以约定开发机、100 个自选以内、单研究 worker 为首期基准；下列是待测试的目标，不是现有实测成绩。

- 本地缓存查询常规接口 P95 小于 300ms，研究入队响应 P95 小于 1s；上游模型/数据耗时单独统计。
- 已持久化研究事件通常 2s 内到达页面；重连可恢复状态，不依赖页面驻留。
- 首次返回有限数量行情柱，平移按需加载；图表库按需加载，列表和历史分页。
- 可见标的刷新、后台标签降频、订阅共享和退订，避免按每个面板重复请求。
- 行情标注预计刷新与实际来源延迟，无法达到实时能力时不显示实时徽标。
- 备份覆盖数据库、报告、研究快照与 schema 版本；恢复演练检查引用完整性。凭据按独立策略备份或重新授权。
- 日志以 run/attempt/node/source/trace 关联，记录错误、限流、调用耗时、缓存命中、队列积压；凭据和私有内容脱敏。

测试重点是配置隔离、角色模型路由、凭据不泄露、自选持久化、任务重启/取消/恢复、SSE 补齐、数据时区/调整/截止时间、资金口径、授权下载及核心报告不丢章节。模型端到端测试使用明确标记的测试适配器；真实模型冒烟测试单独执行并记录条件，不能把 mock 通过写成真实接入成功。

**二十、实施里程碑与交付标准**

| 里程碑 | 交付内容 | 验收门槛 |
|---|---|---|
| M0 技术与契约基线 | 前端脚手架/锁文件、Oxc 质量门禁、主题、Orval/API 契约、数据库迁移、能力矩阵 | 安装无 peer 冲突；生成漂移、格式、lint、TS7、测试、构建通过，现有核心回归通过 |
| M1 研究闭环 | 模型连接、真实密钥配置、角色解析、模板、自选 CRUD、基础数据检测与日线、可靠任务、报告持久化、取消/中断/兼容恢复、SSE 补齐 | 从空配置走通真实个股研究；刷新/重启找回列表与报告；验证取消、兼容恢复及断线补齐 |
| M2 完整个人工作台 | 专业行情、分钟适配、市场脉搏、板块关注、完整数据中心/高级路由、市场简报、可接入的资金视图 | 真实分钟图、真实行业相对收益和同 feed 成交关注；有来源的波动/指定股票池广度证据及简报；研究与行情联动 |
| M3 朋友使用 | 登录、私有/共享范围、权限、配额、部署与备份 | 不同用户数据隔离；Viewer 不能启动计费任务；网络开放前通过检查 |
| 后续产品化 | PostgreSQL/专门队列、数据许可方案、定时/告警、模型评估、机构披露与组合模拟 | 按实际使用量和数据能力分别立项 |

M1 是核心迁移验收点，M1 + M2 才构成本次设计的完整个人版本。M2 的分钟、行业强弱、同 feed 成交关注、波动与指定股票池广度是最低真实能力，数据来源必须落实后才能通过，不能以全页“待接入”或模拟数值通过验收。ETF 净申赎、期权结构等专门数据属于依赖来源的扩展项，未取得时明确记录缺口，不把缺失的资金流分析宣称为已实现。

最终端到端验收场景：新建供应商连接 → 填写 API Key → 选择模型并检测 → 绑定默认/角色模型 → 搜索并加入股票 → 查看有来源与时间标记的行情 → 发起真实 TradingAgents 分析 → 查看四分析师、多空、交易、风险与最终决策 → 导出报告 → 重启后恢复自选和历史 → 从真实市场/板块数据下钻到该股票。另独立演练排队取消、运行中取消、worker 中断、兼容检查点恢复、SSE 断线补齐和凭据无泄露。

实施时先保持旧核心可用；新版核心、数据迁移、导出和恢复验收通过后再切换默认入口。8011 草稿仅用于视觉与交互讨论，不作为正式代码架构或功能完成证明。

旧 JSON 任务与报告只读盘点、备份后按旧 ID/来源哈希幂等导入，保留原文件与导入清单。缺少的运行模型、证据和配置清单标记 legacy/unknown，不补造；旧运行中状态作为历史 interrupted，不能直接由新 worker 自动接管。切换写入口前停止旧入口接收新任务，确认没有双执行；新版 API 兼容层和恢复路径遵守相同权限和命名空间。分阶段实现与回退规则见实现方案。
